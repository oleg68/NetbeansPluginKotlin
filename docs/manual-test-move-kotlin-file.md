# Ручное тестирование: Move Kotlin File

Этот план проверяет refactoring **Move Kotlin File** (F4.1) и исправление отображения source root.

## Подготовка

1. Соберите плагин и установите созданный `.nbm` в тестовый NetBeans.
2. Перезапустите NetBeans.
3. Откройте или создайте Kotlin-проект с исходным корнем `src/main/kotlin` либо `src/main/java`.
4. Для проверок обновления ссылок используйте не менее двух Kotlin-файлов, один из которых импортирует или использует объявление из перемещаемого файла.

## 1. Доступность команды

1. Откройте Kotlin-файл в редакторе.
2. Поместите курсор в файл без выделения текста.
3. Выберите **Refactor → Move Kotlin File**.

**Ожидаемый результат:** открывается диалог Move Kotlin File; команда доступна для Kotlin-файла в редакторе.

## 2. Отображение Source Root

1. В открытом диалоге раскройте список **Source Root**.
2. Если в проекте несколько source root, проверьте каждый элемент.
3. Закройте список и проверьте выбранное значение.

**Ожидаемый результат:** список и выбранное значение показывают краткие проектные имена, например `Source Packages`. Не должны отображаться технические строки вида `KotlinPackageTargetRoot(path=..., displayName=..., folder=...)`.

## 3. Перемещение в корректный пакет с обновлением ссылок

1. Создайте файл `sample/source/Greeting.kt`:
   ```kotlin
   package sample.source

   class Greeting
   ```
2. Создайте использующий его файл, например `sample/client/UseGreeting.kt`:
   ```kotlin
   package sample.client

   import sample.source.Greeting

   val greeting = Greeting()
   ```
3. Откройте `Greeting.kt`, выберите **Refactor → Move Kotlin File**.
4. Выберите нужный Source Root, укажите пакет `sample.target`.
5. Оставьте включённым **Update Kotlin references** и выполните рефакторинг.

**Ожидаемый результат:**

- файл перемещён в каталог `sample/target` выбранного source root;
- в `Greeting.kt` пакет изменён на `package sample.target`;
- импорт в `UseGreeting.kt` изменён на `import sample.target.Greeting`;
- проект остаётся без ошибок компиляции, использование `Greeting()` разрешается.

## 4. Undo Last Refactoring

1. После успешного перемещения выберите **Refactor → Undo Last Refactoring**.
2. Проверьте оба файла и их расположение.

**Ожидаемый результат:**

- `Greeting.kt` возвращён в исходный каталог;
- исходная директива `package sample.source` восстановлена;
- импорт в использующем файле снова указывает на `sample.source.Greeting`;
- состояние редакторов и проекта согласовано.

## 5. Перемещение в другой source root

1. Добавьте в проект второй source root, например `src/test/kotlin`, если его ещё нет.
2. Откройте `Greeting.kt` и запустите Move Kotlin File.
3. В поле **Source Root** выберите второй корень.
4. Укажите пакет `sample.target` и выполните рефакторинг.

**Ожидаемый результат:** файл появляется в `sample/target` именно выбранного source root; значение Source Root остаётся читаемым; package declaration соответствует заданному пакету.

## 6. Несоответствие package и каталога

1. Создайте Kotlin-файл в каталоге, который не соответствует его `package`, например:
   - путь: `sample/wrong/Unexpected.kt`;
   - содержимое: `package sample.declared`.
2. Переместите файл в пакет `sample.target`.

**Ожидаемый результат:** операция задаёт итоговое расположение по выбранному target package и обновляет package declaration на `sample.target`; она не зависит от исходного несовпадения package и каталога.

## 7. Конфликт имени файла

1. В целевом каталоге заранее создайте файл с тем же именем, например `sample/target/Greeting.kt`.
2. Попробуйте переместить туда исходный `Greeting.kt`.

**Ожидаемый результат:** рефакторинг сообщает о конфликте и не повреждает ни исходный, ни уже существующий целевой файл.

## 8. Отключение обновления Kotlin-ссылок

1. Подготовьте файл с Kotlin-импортом перемещаемого класса, как в разделе 3.
2. В диалоге Move Kotlin File снимите флажок **Update Kotlin references**.
3. Переместите файл в другой пакет.

**Ожидаемый результат:** файл и его package declaration перемещены/обновлены, но импорт или ссылки в других Kotlin-файлах автоматически не меняются. Неразрешённая ссылка допустима как ожидаемое следствие отключённой опции.

## 9. Откат при ошибке записи

1. Подготовьте операцию, для которой целевой каталог недоступен для записи, либо воспроизведите другую контролируемую ошибку файловой системы без риска потери данных.
2. Запустите перемещение.

**Ожидаемый результат:** при ошибке операция прекращается корректно; исходный файл, его package declaration и ранее существующие целевые файлы не остаются в частично изменённом состоянии.

## Неподдерживаемые сценарии

Следующие сценарии не входят в F4.1 и не являются критериями приёмки:

- запуск Move Kotlin File из контекстного меню узла файла или каталога;
- рекурсивное перемещение каталогов;
- перемещение не-Kotlin файлов;
- обновление Java usages;
- обновление упоминаний в комментариях, строках и произвольном тексте;
- сценарии, требующие IDEA index-backed filesystem или IDEA project model.

## Результат проверки

Зафиксируйте для каждого раздела: **пройдено**, **не пройдено** либо **не применимо**, а для непрохождения приложите минимальный пример проекта и шаги воспроизведения.
