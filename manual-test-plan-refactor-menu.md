# План ручного тестирования Refactor

## Цель

Проверить, что после установки новой версии плагина контекстное подменю **Refactor** снова отображается для Kotlin-файлов и Kotlin-папок/пакетов, а команды остаются внутри этого подменю.

## Подготовка

1. Закрыть NetBeans.
2. Установить NBM:
   `/home/oleg/my-projects/nbplugins/NetbeansPluginKotlin/Nbm/target/nbm/netbeans-plugin-kotlin-nbm-0.11.294-SNAPSHOT.nbm`
3. Проверить в списке установленных модулей, что активна именно версия `0.11.294` (не прежняя `0.11.293`).
4. Запустить NetBeans и открыть Maven, Gradle или Ant/J2SE проект с Kotlin-файлами.
5. Убедиться, что Kotlin source root содержит хотя бы один `.kt` файл.

## 1. Kotlin-файл

1. В окне **Projects** выбрать Kotlin-файл.
2. Открыть контекстное меню.
3. Проверить, что присутствует пункт **Refactor**.
4. Открыть **Refactor**.
5. Проверить наличие доступных команд, например:
   - **Rename Kotlin File...**;
   - **Change Kotlin Package...** — пункт должен быть **активен** для выбранного `.kt` файла;
   - **Undo Last Refactoring** и **Redo Last Refactoring**.
6. Проверить, что эти команды не появились отдельными пунктами верхнего уровня.
6a. Выбрать в **Projects** Java-файл и проверить, что **Refactor → Change Kotlin Package...** в этом случае недоступен.
7. Открыть Kotlin-файл в редакторе, установить курсор на имя декларации и выполнить **Refactor → Rename...** либо `Alt+Shift+R`. Должен открыться диалог переименования символа, а не **Rename Kotlin File...**.
8. Не закрывая этот файл, вновь выбрать его в **Projects** или **Files** и выполнить **Refactor → Rename Kotlin File...**. Должен открыться диалог физического переименования файла, а не диалог переименования символа в позиции курсора.
9. Выбрать одновременно два Kotlin-файла в **Projects** или **Files**. Проверить, что для них не запускается и не предлагается одиночное **Rename Kotlin File...**.

## 2. Kotlin-папка или пакет

1. Выбрать Kotlin-папку в дереве проекта либо пакет в **Kotlin Source Packages** / **Kotlin Test Packages**.
2. Открыть контекстное меню.
3. Проверить наличие пункта **Refactor**.
4. Внутри **Refactor** проверить команды:
   - **Change Kotlin Package...**;
   - **Rename Kotlin Package Directory...**;
   - **Move Kotlin Directory...**;
   - **Undo Last Refactoring** и **Redo Last Refactoring**.
5. Убедиться, что ни одна из этих команд не отображается вне **Refactor**.

## 3. Открытие Change Kotlin Package

1. Выбрать папку/пакет, содержащий Kotlin-файлы.
2. Открыть **Refactor → Change Kotlin Package...**.
3. Проверить, что открывается диалог рефакторинга.
4. Изменить пакет и применить операцию.
5. Проверить package-директивы Kotlin-файлов и поддерживаемые ссылки.
6. Учесть штатное поведение NetBeans: перед показом любого стандартного non-query refactoring-диалога IDE выполняет `Save All`. Поэтому сохранение уже существовавших правок при выборе **Change Kotlin Package...** ожидаемо.
7. Для проверки живого несохранённого буфера сначала открыть диалог **Change Kotlin Package...**, затем, не закрывая его, добавить в начало уже открытых изменяемого Kotlin-файла и Kotlin-файла с использованием несохранённый комментарий (например, `// unsaved`) и установить курсоры в заметные позиции.
8. Вернуться в диалог, изменить пакет с обновлением ссылок и применить операцию. Убедиться, что комментарии сохранились, package/import-правки внесены в правильные строки, а курсоры остались на прежних логических местах: не перешли ни к package-директиве, ни в конец файла.
9. Выполнить **Refactor → Undo Last Refactoring**. Проверить, что package/import-правки отменены, оба комментария сохранены, а курсоры вернулись в позиции до рефакторинга и не оказались в конце файлов.
10. Повторить изменение пакета и отменить его обычным `Ctrl+Z` в каждом открытом затронутом редакторе. Проверить восстановление исходного текста и позиции курсора без перехода в конец файла.

### Диагностика (только при проблеме)

Если поведение курсора снова окажется неверным, включить `FINE` для двух категорий логгеров
в `~/netbeans/<версия>/etc/netbeans.conf` (в `netbeans_default_options`):

```
-J-Djava.util.logging.ConsoleHandler.level=FINE
```

и в `<userdir>/config/Logger.properties`:

```
io.github.nbplugins.kotlin.nbm.reformatting.level=FINE
io.github.nbplugins.kotlin.nbm.refactoring.changePackage.level=FINE
```

Логи содержат только пути, идентификаторы документов, длины, число хунков и смещения курсора —
без текста исходников.

## 3a. Change Kotlin Package из редактора (главный сценарий исправления)

1. Открыть `.kt` файл в редакторе и поставить в нём курсор (файл в дереве не выделять).
2. Открыть меню **Refactor** (главное меню IDE или контекстное меню редактора) и проверить, что **Change Kotlin Package...** **активен** (не серый).
3. Выполнить **Change Kotlin Package...** и проверить, что диалог открывается с текущим пакетом файла и что предложенный пакет по умолчанию совпадает с объявленным в файле `package`.
4. Изменить пакет и применить операцию. Проверить, что обновилась `package`-директива именно этого файла и поддерживаемые ссылки, физический путь файла не изменился.
5. Выполнить **Refactor → Undo Last Refactoring** и убедиться, что пакет и ссылки вернулись к исходным.
6. Повторить шаги 2–4 для файла, который в дереве **не** выделен, но открыт в редакторе: результат должен быть тем же.
7. Открыть `.java` файл в редакторе и проверить, что **Refactor → Change Kotlin Package...** недоступен.

## 3b. Change Kotlin Package при курсоре на директиве import

Подготовка: в проекте есть Kotlin-пакет `other.pkg`; файл `other/pkg/Widget.kt` объявляет `package other.pkg`,
а в редактируемом файле есть строка `import other.pkg.Widget` и использование `Widget`.

1. Открыть редактируемый файл в редакторе и поставить курсор на строку `import other.pkg.Widget`.
2. Выполнить **Refactor → Change Kotlin Package...**.
3. Проверить, что диалог открывается с пакетом **`other.pkg`** (то есть импортируемым), а не с пакетом самого редактируемого файла, и что в описании указаны файлы, объявляющие этот пакет.
4. Изменить пакет, применить операцию и проверить, что обновилась `package`-директива в `other/pkg/Widget.kt` и все ссылки/импорты `other.pkg` в проекте (включая строку `import` в редактируемом файле), а физические пути файлов не изменились.
5. Выполнить **Refactor → Undo Last Refactoring** и убедиться, что правки отменены.
6. Повторить шаги 1–3 для star-импорта `import other.pkg.*`: выбранным пакетом должен быть `other.pkg`.
7. Поставить курсор на строку `import kotlin.collections.List` (пакет библиотеки) и выполнить **Refactor → Change Kotlin Package...**. Проверить, что вместо диалога появляется информационное сообщение о том, что пакет не объявлен в исходниках проекта, и что пакет самого редактируемого файла при этом не меняется.
8. Поставить курсор в тело файла (вне директив `import` и `package`) и выполнить **Refactor → Change Kotlin Package...**. Проверить, что, как и раньше, предлагается пакет самого редактируемого файла.
9. Выбрать файл в дереве **Projects**, не активируя редактор (курсор в редакторе пусть остаётся на строке `import`), и выполнить **Refactor → Change Kotlin Package...**. Проверить, что в этом случае меняется пакет выбранного файла, а не импортируемый пакет.
10. Повторить шаги 1–4 для файла с несохранёнными правками: результат должен учитывать текущий (несохранённый) текст буфера.

## 4. Move Nested Member: unsafe inner class

1. Создать Kotlin-класс с вложенным классом и `inner`-классом внутри него, например:
   ```kotlin
   class Source {
       class Outer {
           inner class Inner
       }
   }
   ```
2. Установить курсор на `Inner` и открыть **Refactor**.
3. Проверить, что **Move Nested Member...** не предлагается/не применяется для `Inner`.
4. Убедиться, что `Outer` не был ошибочно выбран или перемещён в качестве замены.

## 5. Регрессия F7

1. На Kotlin-файле открыть **Refactor → Rename Kotlin File...**.
2. Выполнить переименование и проверить изменение имени файла.
3. На Kotlin-папке открыть **Refactor → Rename Kotlin Package Directory...**.
4. Выполнить переименование и проверить изменение каталога и сохранение содержимого.
5. Проверить **Undo Last Refactoring** для обеих операций.
6. Для case-only переименований (например, `Before.kt` → `before.kt` и `Before` → `before`) проверить успешное применение и отмену. После операции и отмены рядом с исходными файлами/каталогами не должно оставаться путей с префиксом `.nbkotlin-`.

## Ожидаемый результат

Для Kotlin-файла и Kotlin-папки/пакета контекстное меню содержит **Refactor**. Все Kotlin-команды рефакторинга доступны внутри него; отдельного верхнеуровневого пункта вместо подменю нет.
